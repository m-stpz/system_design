# Dropbox

- Cloud-based file storage service that allows users to store and share files
- Secure and reliable way to store and access files from anywhere, on any device

## The Approach

1. Requirements
2. Core entities
3. API
4. High-level design
5. Deep dives

## 1. Requirements

Functional requirements: what the system does

- Upload a file
- Download a file
- Share a file
- Automatically sync files across devices

Out of scope

- Roll own blob storage

Non-functional requirements: how the system behaves | what informs the deep-dives later on

- Consistency or availability? Availability > consistency
  - it's ok if we update the data and someone when accessing it, sees a "outdated" version for a while
  - functionality should continue working, no matter what. it's fine eventual consistency
- low latency upload and download
- support large files as 50gb
  - resumable uploads
- high data integrity (sync accuracy)

> It's fine to have the initial list, progress to other topics and come back to it and add new stuff here

## 2. Core entities

- User
  - id
  - name

- File
  - content
  - metadata: name, mime_type, owner, id, created_at
  - shared_with?: user[]
  - is_synced,
  - upload_progress?: boolean

## 3. API

Functional requirements

```ts
// Upload a file
POST /files -> id + 200
{
    file,
    file_metadata,
    owner_id,
}

// Download a file
GET files/{id} -> file

// Share a file
PATCH files/{id} -> id
{
    shared_with: user[]
}

GET files/{id} -> file

// Automatically sync files across devices (call out the upload/download endpoints)
// - we need to know what's changed
// - the changes that happened within that workspace
// - everytime we do a change to some file, we need to write a "log" here
GET /changes?since={timeStamp} -> File['id'][]
```
